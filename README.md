# Pitchord

用于校对歌曲歌词时间的本地桌面编辑器。本阶段完成句级和字级时间编辑。界面规范见 [design.md](./design.md)。

## Windows 轻量便携包

Release 提供一个压缩包：`Pitchord-<版本>-windows-x64.zip`。将其中的 `Pitchord` 文件夹解压到任意本地磁盘和任意可写位置，再双击 `Pitchord.exe`。软件包内含桌面程序和 FFmpeg，不再内置体积很大的 Python、PyTorch 和模型。

第一次打开时会出现“分析环境设置”：

1. 推荐选择“创建独立环境”。默认安装到程序根目录的 `environment`，也可以选择 D 盘等任意可写位置。
2. “自动选择”会检测 NVIDIA 显卡；检测到可用设备时安装 CUDA 12.1 计算组件，运行检查失败会自动回退 CPU。用户也可以明确选择 CPU 或 CUDA 12.1。
3. 已经自行准备环境的用户可选择“使用现有 Python”，指定 Python 3.10–3.12 的 `python.exe`。Pitchord 只检测和使用该环境，不会自动修改或删除它。
4. 人声分离与歌词对齐模型在第一次使用相应功能时按需下载。

受管理的 Python、分析依赖、模型和缓存都位于所选 `environment`。默认环境随整个 Pitchord 文件夹移动；删除文件夹即可同时卸载软件和环境。选择其他位置时，可在“设置 → 存储与环境”删除 Pitchord 管理的数据。歌词工程保存在新建工程时选择的位置，不会因为删除程序文件夹而自动删除。

开发时可以运行：

```bash
pnpm desktop:start
```

生成轻量便携压缩包：

```bash
pnpm desktop:package
```

构建过程不会打包本机 Python、模型或 `offline-analysis`。Python 依赖声明位于 `scripts/pyproject.toml`，运行组件分别由 `scripts/analysis-requirements.txt`、`scripts/analysis-torch-cpu.txt` 和 `scripts/analysis-torch-cu121.txt` 固定。`scripts/analysis-lock-win-x64.txt` 保留用于离线环境复现。

## 开发版网页预览

需要 Node.js 20.19+ 或 22.12+ 与 pnpm。

```bash
pnpm install
pnpm dev
```

打开终端显示的本地地址。`pnpm build` 构建，`pnpm test` 检查歌词编辑规则。

## 当前流程

1. 新建工程，指定名称和存放位置（默认在“文档/Pitchord Projects”）；然后导入音频或视频。原文件会复制到工程的 `media` 文件夹，不上传媒体。
2. 导入 LRC 文件或粘贴普通歌词。普通歌词会先按媒体时长均分，随后人工校对。
3. 在句级视图编辑文本与时间。拖动歌词矩形或左右手柄，连续选中后合并；点击时间轴或按空格暂停可设置全局辅助线，边界靠近时自动吸附，分割时也直接采用该位置。文字分割默认参考中英文标点和空格。删除只删除标注。
4. 在字级视图逐字调整。初始字界是均分建议，所有字界都限制在所属句内。
5. 双击已选中的时间块进入范围调整并循环试听。拖动结束边界时，一次拖动过程中只更新循环终点，不会反复跳回；按 Enter 保存，按 Esc 放弃。撤回与重做支持编辑操作，也可保存完整 `.pitchord.json` 项目或导出句级 LRC。
6. 首次准备分析环境后，在模型管理中下载 HTDemucs 或其他 Demucs 模型；也可一次选择 MSST `.ckpt` 与配套 YAML 导入自己的模型。当前 MSST 提供者可直接运行常见的 MelBandRoformer 与 BSRoformer，模型文件复制到 Pitchord 的独立环境。功能页只显示已经安装且可以运行的模型。
7. 每次人声分离都保存独立的纯人声与纯伴奏结果，可以随时切换，并作为后续音高识别的输入。原声、纯人声和纯伴奏可分别开关、调节音量与叠加试听；视频画面保持不变。
8. 连续音高只从明确选择的纯人声结果生成。桌面版可选择 pYIN 或 TorchCrepe；每次识别结果都独立保存并可实时切换，字级匹配和字幕跟随当前结果。字级编辑中可同时查看模型建议与实际字幕音高，用 `E4`、`E4-F4-E4`、`E4~` 或 `—` 手动修改，并精确调整多个音之间的换音时间；人工结果可以撤回或恢复模型建议。浏览器预览继续使用基础自相关算法。
9. “歌词时间戳匹配”使用明确选择的纯人声结果。导入 LRC 时，时间标签和元信息不会混入歌词文字；歌词逐句作为最终文本，原有时间标签仅作为弱时间提示，以区分重复段落。没有时间标签的纯歌词也能对齐。faster-whisper 提供识别字词和时间戳；程序使用单调文本匹配，为漏识别的整句保留合理时长，再在句内分配单字时间，避免将歌词挤进相邻识别词之间的极短空隙。完成后会提示缺少可靠识别、建议重点复核的句号。每个模型的结果分别保存，应用后可撤回并继续人工校准。默认 Whisper Small 模型保存在 `environment/models/whisper`。
10. “字级字幕与视频”可导出带逐字时间、逐音音名与时值的 JSON，或导出 ASS。默认 ASS 会在当前字下方显示“・”，按逐音结果改变当前字颜色，在字上方显示当前音名，并在字间空隙保留上一音高。字级编辑显示的音高及人工修改与导出结果共用同一份数据。视频工程可使用内置 FFmpeg 直接生成带字幕的 MP4，结果保存在工程 `exports`。

导入媒体、环境安装、环境检测、人声分离和音高识别等长任务会显示在右下角“任务进度”中。面板可收起、重新展开，并保留本次运行的完成、失败和取消记录。环境依赖安装、人声分离、TorchCrepe 音高识别及歌词时间戳匹配可从任务中心取消，后台进程与子进程会一并结束。

桌面工程会自动保存 `project.pitchord.json`，并把原媒体放在 `media`，把人声分离的 WAV 放在 `analysis`。歌词另存于 `lyrics/current.lyrics.json` 和 `lyrics/current.lrc`；历史版本在 `lyrics/backups`，导入的 LRC 或粘贴原文在 `lyrics/sources`。点击“歌词备份”可查看文件，点击“恢复歌词”可选择一个历史 JSON 版本恢复；恢复本身也可撤回。点击“工程文件夹”可直接用其他播放器试听原媒体、人声与伴奏。打开工程时会自动恢复保存的媒体与分析音轨。网页预览仍使用浏览器本地歌词草稿。

## 目前边界

- 字级初始范围是可编辑的时间建议。文字变化时，未变化的首尾字尽量保留其时间；必要时会重新分配时间，需复核。
- “运行人声分离”直接处理工程内的原始媒体，不会再次要求选择文件。桌面版根据所选模型调用 Demucs 或内置的 MSST 推理提供者，同时生成纯人声和纯伴奏 WAV，并保存到工程的 `analysis/separation-*`。分离音轨用同一个 Web Audio 时钟混音，切换开关或音量不重启音频；人声和伴奏可增益到 200%。也可以使用“导入外部人声结果”载入已有的人声 WAV/MP3。桌面包已内置 FFmpeg/FFprobe，可直接处理 MP4 等视频。
- 分析环境和模型不写入工程，也不修改系统 Python 或 PATH。默认使用 `<Pitchord 根目录>/environment`，用户可以在首次向导中改到其他磁盘，或指定已有 Python。自动配置会根据 NVIDIA 检测结果选择 CPU 或 CUDA 12.1 PyTorch，并以安装后的实际运行检查为准。Demucs、MSST 和 TorchCrepe 在 CUDA 可用时使用 GPU。Hugging Face 的未登录提示会被当作普通提示过滤；公共模型下载不要求用户提供 Token，真正发生限流或网络错误时界面会显示可执行的重试说明。
- pYIN 适合较干净的纯人声并带有概率有声判断与时间连续性，始终使用 CPU；TorchCrepe 是可使用 CUDA 的歌声音高神经网络方案。RMVPE 已纳入算法目录，但在可再分发模型权重和推理依赖确认之前不会显示为可用。歌词强制对齐通过 faster-whisper 运行，CTranslate2 CUDA 可用时使用 GPU，初始化失败会自动回退 CPU；声区（真声/假声/混声）标注仍属于后续增强项。
- 分割时间可由播放头指定；未指定时参考句中附近的波形音量低谷。它仍需人工试听确认。
- LRC 只保存句级起点。完整句界、字界与人工调整保存在 `.pitchord.json` 中，也可转换为字级 JSON 或 ASS 字幕。ASS 的动态音高样式依赖当前选中的音高识别结果。
- 视频波形依赖浏览器对音轨格式的解码支持；无法提取波形时，视频仍可播放并编辑时间标注。

分析模块结构与后续模型接入边界见 [docs/analysis-architecture.md](./docs/analysis-architecture.md)。
