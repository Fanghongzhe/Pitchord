# Pitchord

用于校对歌曲歌词时间的本地桌面编辑器。本阶段完成句级和字级时间编辑。界面规范见 [design.md](./design.md)。

## 启动桌面版（Windows）

直接双击 `release-desktop/Pitchord-0.1.0-x64-portable.exe`，不需要打开浏览器或安装 Node.js。它是便携版，会在本机保存草稿；音频和视频仍只在本机处理。

开发时可以运行：

```bash
pnpm desktop:start
```

生成新的便携版：

```bash
pnpm desktop:portable
```

如果需要安装向导，可使用 `pnpm desktop:installer`。

## 开发版网页预览

需要 Node.js 20.19+ 或 22.12+ 与 pnpm。

```bash
pnpm install
pnpm dev
```

打开终端显示的本地地址。`pnpm build` 构建，`pnpm test` 检查歌词编辑规则。

## 当前流程

1. 新建工程，指定名称和存放位置（默认在“文档/Pitchord Projects”）；然后导入音频或视频。原文件会复制到工程的 `media` 文件夹，不上传媒体。
2. 导入 LRC 文件或粘贴普通歌词。普通歌词会先按媒体时长均分，随后人工校对。
3. 在句级视图编辑文本与时间。拖动歌词矩形或左右手柄，连续选中后合并，选择文字和音频分割点后分割。删除只删除标注。
4. 在字级视图逐字调整。初始字界是均分建议，所有字界都限制在所属句内。
5. 使用“循环试听本句”验证。撤回与重做支持编辑操作，也可保存完整 `.pitchord.json` 项目或导出句级 LRC。
6. 在“音频处理与分析”区域先选择是否进行人声分离。分离完成后，原声、纯人声和纯伴奏可分别开关、调节音量与叠加试听；视频画面保持不变。连续音高只从纯人声轨生成，音高轨会叠加到时间轴，并按字级范围显示音名和基础运动类型。

桌面工程会自动保存 `project.pitchord.json`，并把原媒体放在 `media`，把人声分离的 WAV 放在 `analysis`。歌词另存于 `lyrics/current.lyrics.json` 和 `lyrics/current.lrc`；历史版本在 `lyrics/backups`，导入的 LRC 或粘贴原文在 `lyrics/sources`。点击“歌词备份”可查看文件，点击“恢复歌词”可选择一个历史 JSON 版本恢复；恢复本身也可撤回。点击“工程文件夹”可直接用其他播放器试听原媒体、人声与伴奏。打开工程时会自动恢复保存的媒体与分析音轨。网页预览仍使用浏览器本地歌词草稿。

## 目前边界

- 字级初始范围是可编辑的时间建议；连续音高使用本地自相关基线，适合人工复核，不等同于最终的歌声专用模型。文字变化时，未变化的首尾字尽量保留其时间；必要时会重新分配时间，需复核。
- “运行人声分离”直接处理工程内的原始媒体，不会再次要求选择文件。桌面版调用 `scripts/separate-vocals.py`，使用本机 Demucs 同时生成纯人声和纯伴奏 WAV，并保存到工程的 `analysis/separation-*`。分离音轨用同一个 Web Audio 时钟混音，切换开关或音量不重启音频；人声和伴奏可增益到 200%。也可以使用“导入外部人声结果”载入已有的人声 WAV/MP3。桌面包已内置 FFmpeg/FFprobe，可直接处理 MP4 等视频；首次使用仍需要本机安装 Python、Demucs 及其模型权重。启动时会在便携包目录及其上两级内查找 `.venv-analysis`、`.venv`、`venv`；手动选择的 `python.exe` 会被记住，也可以通过 `PITCHORD_PYTHON` 指向已有 Python 环境。
- 当前连续音高是可解释的本地自相关分析；歌声专用音高模型、声区（真声/假声/混声）标注和更强的歌词强制对齐仍属于后续增强项。
- 分割时间可由播放头指定；未指定时参考句中附近的波形音量低谷。它仍需人工试听确认。
- LRC 只保存句级起点。完整句界、字界与人工调整保存在 `.pitchord.json` 中。
- 视频波形依赖浏览器对音轨格式的解码支持；无法提取波形时，视频仍可播放并编辑时间标注。
