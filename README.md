# Pitchord

在练习歌曲的过程中，我们通常对每一句歌词的音高很感兴趣，目前在bilibili生产这样音高标注视频的创作者们效率通常不高，这个工具是为了提高他们的效率，借助一定的工具的算法生成一个大概的音高标注版本，并提供较为直观的界面和便捷的操作来让使用者人工检验并修正结果。

Pitchord 是一款 Windows 本地桌面工具，用来把歌曲音频或视频与参考歌词对齐，校对每个字的时间，并制作随音高变化的动态字幕。自动分析给出初稿；波形、频谱、音高曲线和实时预览帮助你快速找到并修正不准的字界。

## 能做什么

- 导入音频或视频及 LRC／纯文本歌词；自动保存工程，也可从最近项目直接继续编辑。
- 首页可刷新工程列表、单选或多选工程、复制完整工程、在文件夹中定位，或将选中工程移入系统回收站；“从最近列表移除”不会删除文件。
- 分离人声与伴奏，并可选用 BS-RoFormer Karaoke 进一步分离主唱与和声。模型按需准备，不随安装包提供。
- 从选定的人声轨提取连续音高；可选 pYIN、TorchCrepe、RMVPE 或 FCPE，不同算法的结果分别保留并可切换。用参考歌词生成句级、逐字时间建议；人工修改不会要求重新做人声分离或音高识别。
- 在同一时间轴查看人声波形、频谱、F0 曲线和逐字区间。拖动字界时可吸附声学候选，锁定已确认的边界，并按异常提示优先复核可疑位置。
- 单字时间轴可按需显示 C4、D4 等音名辅助线，并调节辅助线密度、F0 纵向显示范围和纯人声波形高度；这些仅改变画面，不改变音频或识别数据。
- 可开启“实时适配每句音高范围”：切句、合并、拆分和调整句范围后自动重算 F0 显示范围；音高轨窗口高度也可调节，以便看清音高曲线。视频素材可打开软件内悬浮小窗，从顶栏或画面拖动、从右下角调整大小，并与主播放器同步预览字幕。小窗获得焦点后可用左右键跳转 5 秒、Shift＋左右键微调 1 秒、空格或 K 键播放／暂停、Home／End 跳到开头／结尾；跳转不会主动暂停播放。
- 一边试听一边查看动态字幕：字色映射到可选或自定义的音高色带，当前字由下方强调点标示。视频预览旁可直接打开完整样式设置，在真实视频画面上边调边看；预览是实时近似效果，不需重新编码视频。
- 字唱过后保留选定的音高标记，可选择最后、最低、最高或时值最长的音高；字色保留该字音高序列中最后一音的颜色。
- 导出句级 LRC/SRT、逐字音高 JSON 或 ASS；视频工程还可导出嵌入字幕的 MP4。

## 下载与首次使用

1. 在[最新正式版页面](https://github.com/Fanghongzhe/Pitchord/releases/latest)下载 Windows 便携压缩包。
2. 将压缩包中的 `Pitchord` 文件夹完整解压到可写的本地位置，双击 `Pitchord.exe`。程序本体无需传统安装。
3. 首次需要音频分析时，按“首次准备分析环境”的提示选择推荐配置。Pitchord 会准备独立的 Python、分析依赖和所选模型；这一过程需要网络、磁盘空间和时间。也可以选择已有的 Python 3.10–3.12 环境。
4. 新建工程，导入歌曲和歌词。建议按“人声分离 → 连续音高 → 歌词时间戳匹配 → 逐字复核 → 字幕导出”的顺序工作；也可使用界面中的一键继续处理。

分析环境默认放在程序同目录的 `environment`，也可以在首次设置时选择其他磁盘。推荐的人声分离模型和歌词对齐模型按需下载；去和声模型是可选项。没有 NVIDIA 显卡也可使用 CPU，只是部分分析任务会更慢。

RMVPE 和 FCPE 是可选音高模型，不会在“轻量”“推荐”配置中额外下载；勾选后会随环境准备安装。RMVPE 另需约 360 MB 权重，当前使用 CPU ONNX 推理；FCPE 的约 40 MB 权重随其软件包安装，可使用 CUDA。它们约每 10 毫秒给出一个音高采样点，但这不等同于歌词换字边界的准确度。若已有分析环境，可再次打开“分析环境”勾选模型并准备；原有音高结果不会被覆盖。

v1.1.5 修复了只选 FCPE 时可能漏装音高识别公共组件、却错误显示环境安装成功的问题。旧环境如遇“尚未准备 FCPE”，在“分析环境”中重新准备所选环境即可；无需删除已有模型。HTDemucs 与 HTDemucs FT 的原版权重现在优先从国内 HF Mirror 下载，逐文件校验 SHA-256、支持断点续传，国内线路失败时明确提示并切换 Demucs 官方线路；进度中会显示当前线路。MDX Extra Q 仍使用 Demucs 官方下载机制。

下载线路并非所有组件都固定“国内优先”：Python、PyTorch 和 Python 依赖会自动测速选择国内或官方源，Whisper 也会测速；HTDemucs（含 FT）、去和声权重和 RMVPE 权重优先尝试 HF Mirror。镜像域名不保证大文件最终由国内服务器直传，实际速度应以进度显示为准；MDX Extra Q 目前只有 Demucs 官方下载路线。Windows 版的 uv 安装工具已打入程序包，无需另行下载。

歌词列表的“整体偏移”入口集中提供自定义秒数、常用 ±1/±5 秒、按第一句目标起点计算偏移，以及恢复本轮整体偏移前的位置。单独改动歌词后，恢复入口会停用，避免覆盖刚做的逐句修改；此时可用撤销记录。逐字时间主要由参考歌词与 Whisper 时间戳匹配并插值得到，紫色声学候选线不参与自动划分，仅在手动拖动字边界时辅助吸附。

整体偏移只移动歌词和字的时间范围，不会移动已识别的连续 F0 数据。字的音高会按修改后的时间范围重新读取；若一个听起来稳定的字仍列出许多音名，可能是原始 F0 误判，或音高恰在半音分界附近反复取整。v1.1.6 会把短暂跳动与分界附近的稳定声音合并为更易校对的建议，原始 F0 轨迹仍保留。

v1.0.1 起，内置 Python 下载会按所选线路在国内镜像与官方源之间自动切换，并校验完整文件；可选去和声模型也有国内镜像与官方源备用。若仍失败，界面会显示具体失败线路和原因，已收到的文件片段会用于续传。

v1.1.0 起，Windows 版附带经过校验的 `uv` 高速安装工具；首次环境准备的“Python 与高速安装工具”步骤不再需要临时下载该工具。后续 PyTorch、分析依赖和模型仍会按需联网下载，所需时间取决于所选 GPU/CPU 配置与网络。

> 自动对齐和声学候选都只是建议。长音、连读、弱辅音、重复歌词等场景仍应试听复核；音高跳变不能单独证明换字。

## 工程文件与隐私

工程保存在新建时选择的文件夹。外部导入的音频、视频和人声轨会先复制进工程；之后的试听、波形与分析使用工程副本，原文件移走也不会影响工程。原媒体、人声分析结果和导出文件分别存于工程内的 `media`、`analysis`、`exports`；歌词原稿及其历史版本存于 `lyrics`。Pitchord 在本机处理媒体，不会上传歌曲或歌词；首次准备环境和模型时会联网下载相应组件。

旧工程可以在首页从最近项目直接打开，也可以从文件夹打开。删除程序目录不会自动删除另存的工程；删除整个便携程序目录则会移除其中默认存放的分析环境。若环境放在其他位置，可在“设置 → 存储与环境”中查看和清理。

首页“刷新”会重新检查最近记录，并查找默认工程目录中新加入的工程。复制工程会保留媒体与分析结果，并把副本内部的结果路径改为副本位置；删除工程会先确认，再把整个工程文件夹移入系统回收站。若只想整理首页，请选“从最近列表移除”。

v1.1.1 修复了从项目卡片菜单删除工程后，确认弹窗关闭但首页无法继续点击的问题。

v1.1.2 调整了默认视频字幕效果：未唱到的字保持普通颜色，演唱时随实时音高变色，唱过后保留末尾颜色；当前字的小圆点与上方音高标注更加贴近汉字，带空格的歌词也会按实际字宽定位。

v1.1.3 修复了导出视频中歌词与音高标注、强调点仍可能逐渐错位的问题：三个元素现在共用每字坐标。色带设置移入独立弹窗，支持查看当前工程识别音域、套用冷／灰／暖三段推荐，以及按音名设置多个统一色或线性渐变区间（含端点规则与区间外颜色）。导入后的媒体和人声轨也改为立即读工程副本，后续工作不依赖原路径。

v1.1.6 改进了逐字音高归纳：稳定 F0 在相邻半音界线上轻微摆动时不再拆成大量音名，短于最低持续时间的交替段也会持续合并。字幕预览和 ASS／视频导出现在会给每个已唱过的字保留一个音高标记，可选最后、最低、最高或时值最长；字色保持该字音高序列中最后一音的颜色。原始连续 F0 数据不会因这些归纳规则而改写。

v1.1.9 修复了逐字音高列表与动态字幕混用不同音高来源的问题：歌词上方音名、歌词字色及唱后保留标记均以单字列表的音高序列为准。右上角“原始 F0”不会覆盖已归纳或人工修改的字幕音高；默认仅供校对，也可在导出设置中选择“嵌入视频”，独立设置其位置、字号和边距，颜色复用歌词音高色带。调整字界时预览立即按新时间范围重新匹配音高；保存后生成的 ASS／视频使用同一字幕时序逻辑。浏览器与视频编码器的字体绘制仍可能有少量像素差异，精确字体效果以导出视频为准。

v1.2.0 增加同类段落复用：在歌词列表用 Shift 连续选句，标记为 A、B 等类别，软件按歌曲顺序编号为 A1、A2、A3。打开“已识别到的同类段落”可核对每句和每字的对应，允许多字对应一字、不同字数或行数；之后依次给目标段指定首句起点，预览并同步整句／逐字时值和音高。音高可按半音整体升降，目标段已有人工音高默认保留；锁定边界、越界或与其他歌词重叠时先提示冲突，默认不覆盖。模型建议与人工音高分别保留，可逐字切换哪一份作为字幕结果。原始连续 F0 不会因段落同步而改写；仍建议逐段试听核对变调、转音和实际演唱速度。

v1.2.1 将段落标记移入独立窗口，歌词列表只保留入口与 A1／A2 等标记。对应关系核对改为上下两排歌词、下划线和连线的可视化界面，点击目标句或字／词，再点击来源即可修改；按 Shift 可扩展连续对应范围，详细调整仍可展开。英文单词（如 wo、yeah、Wu）按一个字／词单位参与对应，支持连续的一对多、多对一。句数或字／词数不同时会先给出建议对应，但必须逐句确认后才能同步；跳过中间字或交叉对应会阻止同步并提示原因。

v1.2.2 支持跨便携包复用旧版分析环境：在“分析环境 → 复用整套环境”中选旧版 Pitchord 的整个 `environment` 文件夹，而不是里面的 `python.exe`。软件会同时切换 Python、模型与缓存目录，检查已准备的人声、音高、去和声和 Whisper 歌词对齐模型，不复制或重新下载旧文件。旧方式选中该环境里的 `python.exe` 时也会自动识别对应的整套目录；单独的第三方 Python 仍可只作为 Python 使用。切换环境不会删除旧版便携包，复用期间也必须保留旧环境文件夹。

v1.2.3 让空格键与播放器按钮的播放／暂停行为一致：暂停不会移动歌词分割辅助线，点击时间轴才会设置辅助线。“标记同类段落”窗口可直接清除所选段落或逐项清除，也能在确认后清除全部标记；清除首个同类段落时会重排编号并重置依赖旧来源的对应关系，不改动已编辑的歌词时间和音高。

v1.2.4 修正句级时间轴的“添加句”：已有选中句时，新句接在所选范围右侧，与右键落点无关；没有选中句时，以右键所在时间为起点寻找可用空隙。横向滚动时间轴后的右键时间换算也已修正；歌词列表的右键“添加句”同样可用。

单字时间轴的“音高视图”可按需打开音名辅助线并选择密度；F0 显示上、下限可拉近，也能按当前句自动适配。纯人声波形另有独立的显示增益。以上都只是可持久保存的画面设置，不改变音频、原始 F0、逐字匹配或导出结果。

## 开发与构建

开发环境需要 Node.js 20.19+ 或 22.12+ 和 pnpm：

```bash
pnpm install
pnpm desktop:start
```

常用检查与 Windows 便携包构建：

```bash
pnpm test
pnpm build
pnpm desktop:package
```

分析架构见 [docs/analysis-architecture.md](docs/analysis-architecture.md)，界面与逐字标注约定见 [design.md](design.md)。第三方组件说明见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。
